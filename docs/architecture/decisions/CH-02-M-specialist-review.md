For p,s above, storage maximum = 10^(p−s) − 10^(−s). Candidate business cap 9,999,999.99 is deliberately a review proposal, not evidence of merchant needs; Finance may lower/raise it within capacity or reject every candidate. None of these options is implemented. [PostgreSQL numeric documentation](https://www.postgresql.org/docs/current/datatype-numeric.html) explains scale coercion and overflow. [Prisma PostgreSQL mappings](https://www.prisma.io/docs/orm/v7/core-concepts/supported-databases/postgresql) documents Decimal/native NUMERIC mapping. Public documentation was reviewed 2026-10-22; no target version or behavior was probed.

Shared candidate policy for review (not approval): accept finite nonnegative exact decimal strings in a bounded grammar, no sign/exponent/whitespace/NaN/infinity, at most the candidate's fractional-digit count; reject excess digits even if trailing zeros. Pad only for canonical serialization (F-A `"12.3400"`, F-B/C `"12.34"`) without changing value. Reject negatives, including lexical `"-0.00"`. No JS Number conversion. A NUMERIC(p,s) column coerces before row CHECK: a scale CHECK on that column cannot detect the original overprecise input. Backend validation and restricted trusted writers are required; if rejecting overprecision for direct DB writers is required, Data must approve a guarded unscaled-numeric ingress before casting, not claim typmod alone rejects it. Review and test this boundary explicitly.

Zero choices: Z1 reject unit_price=0 (recommended review default until free-SKU policy exists); Z2 allow zero explicitly with approved publication/checkout semantics. Baseline's nonnegative example does not decide free goods. Compare-at choices: C1 NULL or >= unit_price (recommended review candidate); C2 NULL or strictly > unit_price; C3 another signed display rule. Neither relationship is approved by baseline's independent nonnegative checks. Optional compare_at_price is subject to same scale/cap/negative rules. Both prices use explicit `currency CHAR(3)`, EGP-only CHECK/default per P0 baseline; no free-form/multicurrency fallback. Price changes affect current catalog only; later quote/order unit/total/currency/rule snapshots remain immutable under their separately signed contracts. Do not copy a current catalog lookup into historical pricing or assume a catalog scale decides aggregated totals.
