## Scope and architecture assessment

The coherent core is a single merchant, Egypt-first physical-goods store in EGP. P0 is registered/verified sandbox purchase, public catalog, durable cart, immutable orders, SKU inventory, basic fulfillment, granular staff access and audit. P1 adds cancellation, returns/refunds, promotions, reviews/wishlists, advanced customer/finance/reporting and notifications. P2 remains research. No live payment activation follows from MVP completion.

Two separate Next.js apps call one NestJS modular monolith. Only API and trusted worker domain services access PostgreSQL; shared UI/types/validation/client packages carry no database credentials or authoritative business logic. Public SEO rendering, private no-store caching, principal-scoped query caches and active-route fetching are required. Redis delivery cannot replace DB reservation/effect truth. The data design correctly prioritizes NUMERIC, snapshot immutability, restricted historical deletion, conditional stock writes, provider event/effect uniqueness and transactional provenance. These are design strengths, not verified behavior.
