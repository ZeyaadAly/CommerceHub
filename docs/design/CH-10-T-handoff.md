## Direction and tokens — approval D1/D2/D3

Premium, restrained retail and efficient SaaS administration share semantic foundations. Keep dark ink, blue actions, light neutral surfaces, modest elevation and readable data from UX §7; no oversized gradients, glows or marketing-style admin. Existing apps are matching static placeholders with Arial and Tailwind imports; `packages/ui` exports an empty boundary. No existing design system is being replaced.

Map these to Tailwind/shadcn semantic variables, including `destructive` → danger and explicit paired foregrounds. Selected includes mark/text, disabled remains readable with explanation where needed, loading keeps its label/width and exposes busy status. No arbitrary alpha-derived text/status colors.

## Component architecture and review boards — approval D4

Keep Next.js App Router/React, Tailwind, shadcn/ui/Radix. Lucide React icons need accessible names when actionable, otherwise hidden from assistive technology. Retain React Hook Form/Zod adapters without business schemas; Recharts waits for separately authorized analytics with text/table alternatives. No installations in this readiness task.

| `packages/ui` presentation primitives      | Required variants / interaction contract                                                                                                                                               |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Button / IconButton                        | Primary, secondary, outline, ghost, destructive; pending/disabled; icon-only accessible label; no nested interactive elements                                                          |
| Input / Textarea / FormField               | Visible label, helper/error association, required/invalid states; controlled/uncontrolled contract; errors preserve typed input; password reveal is explicit                           |
| Select / DropdownMenu / Checkbox / Switch  | Keyboard selection/typeahead where applicable, mixed checkbox state, distinct selection and focus; switch only for immediate binary setting, not fake save                             |
| Dialog / AlertDialog / Sheet               | Title/description, deliberate initial focus, trap/restore focus, Escape and visible close; destructive confirmation initially favors safe action; no native confirm replacement logic  |
| Card / Badge / Tabs                        | Semantic headings, text statuses with caller-supplied severity; keyboard tab pattern, selected state distinct from focus; no domain status mapping                                     |
| Table primitives / Pagination              | Native table/caption/headers; caller-supplied controlled pagination state, accessible current/disabled links; no page-size default, fetch, sorting engine or business row model        |
| Skeleton / EmptyState / ErrorPanel / Toast | Loading/empty/error/success/pending distinctions; meaningful status region, skeleton hidden from screen readers, persistent error/retry panel; toast supplements durable inline result |
| Navigation primitives                      | Skip link, accessible link/breadcrumb, focusable menu/sheet/tooltip building blocks; apps own routes, permissions and shell composition                                                |

Reusable containers may be shared; domain labels, transitions, data fetching and monetary interpretation must not enter UI primitives. UI visibility grants no permission. APIs remain authoritative; client/server state and private cache handling stay with their later owning milestones.

The implementation review canvas must show **the same primitives in two compositions**: storefront heading/product-image placeholder + actions + form; admin title/action toolbar + compact table + pagination. Use synthetic nonbusiness content, no new production/demo routes or catalog/KPI promises. At 360px use a stacked retail block and stacked admin toolbar/card alternative; at 768px a 2-column retail composition and compact scoped table; at 1440px constrained content, retail imagery priority and dense admin rows. This is a component-state blueprint, not approval of future feature-page wireframes required by UX §14.
